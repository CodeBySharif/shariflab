## Findings

Reply with the numbers you want fixed (e.g. `1, 2, 5, 8`). Numbers not listed will not be touched.

### HIGH (Hard Gate)

1. **Product promises analytics that do not work for the owner** — R-38, R-36, C-5, C-3
   Login tagline (“hub & analytics”), primary card CTA “Analytics”, default `trackingEnabled: true`, and a full analytics tab set present a metrics product. Owner reports tracking still fails after embedding the script. Shipping zeros and empty charts as “analytics” is wrong content. Prefer hub-only: open / edit / delete projects; demote or remove analytics until proven.

2. **Em dashes in user-facing copy** — R-02
   - `ProjectsPage.tsx`: “Save your site secret — shown once”
   - `ProjectFormPage.tsx`: “Capture failed — check the website URL…”
   (Code comments with `—` are lower priority; user-visible strings first.)

3. **Missing error states on data views** — R-27
   Projects list, analytics queries, and several mutations lack clear `isError` / `onError` UI. Failures can look like empty data. Empty / loading exist in places; error does not consistently.

4. **Create-project and save-edit failures are silent** — R-26, R-27
   `createMutation` and edit save have no user-visible failure path (no toast / alert on error). Interactive actions that fail without feedback fail the craftsmanship bar.

5. **Input focus outline removed without a clear custom replacement in CSS utilities** — R-32
   `index.css` `.input { outline: none; }` relies on border-color change only. Border-only focus is easy to miss and may fail non-text contrast expectations depending on theme. MUI fields are better; orphaned utility still ships.

6. **Edit layout locks viewport scroll** — R-03, C-4
   Layout sets `overflow: hidden` on edit routes. On short viewports / zoom / mobile keyboard, content can become unreachable.

### MEDIUM (Purpose-Gate / product honesty)

7. **Hub primary action is “Analytics”, not “Open site”** — R-15, R-20, C-3, DESIGN.md screen job
   Card hierarchy sends the user into metrics first. For a hub, the deciding action is visit the project (external URL). Analytics (if kept) should be secondary.

8. **Cards show “N views” that read as insight when tracking is dead** — R-17, R-38
   `pageViews7d` on every card presents a metric without proving the pipeline works. Empty/wrong zeros mislead.

9. **Tracking enabled by default on create** — R-38, DESIGN.md
   Checkbox defaults to on, then pushes a secret snippet. For a hub-first product with broken tracking, default should be off (or the feature removed).

10. **Tracking tab can show a non-working snippet placeholder** — R-38, R-26
    Until secret rotate, UI can invite copying `YOUR_SITE_SECRET` (or similar incomplete state). That is a dead instruction dressed as a working embed.

11. **Charts hardcode dark tooltip/grid colors** — R-34, R-21
    `ProjectAnalyticsPage` `CHART_*` / `TOOLTIP_STYLE` ignore light mode. Theme toggle ships both modes; light charts break hierarchy/contrast.

12. **Glass / blur on platform chip without a written hierarchy reason** — R-10
    Thumbnail overlay chip uses `backdropFilter: blur(4px)`. Allowed as accent only; currently decorative frost on a small label.

13. **Orphaned Tailwind marketing CSS vs MUI app** — R-20, R-31, C-1
    `index.css` defines `.btn-primary`, `.card`, `.hero-band`, `.toast`, etc. while the app is MUI-first. Dual systems weaken identity and invite sterile / inconsistent defaults.

14. **Generic / mismatched empty-state copy** — R-15, R-16 (soft), C-3
    “Use **Add** in the navbar to get started” does not match the control label “Add Project”, and “get started” is a generic CTA phrase.

### LOW (Quality locks / polish)

15. **Identical project-card composition everywhere** — R-14
    Every project is the same card shell (thumb, name, notes, chips, three actions). Fine for a catalog if hierarchy lives in the primary action; currently flattened because Analytics is equal weight to Edit/Delete and Open is icon-only.

16. **Dark mode as default without owner-stated tool reason in UI** — R-21
    Default dark is plausible for a personal lab tool (DESIGN.md agrees dark-first). Finding is low: keep dark-first once documented; verify light fully (see #11).

17. **No project-not-found state** — R-27
    Bad `/projects/:id` can leave blank/ellipsis chrome instead of an honest “project not found” + back to hub.

18. **README / product mismatch (email auth, analytics emphasis)** — R-38
    Docs still sell email/password and analytics as core. Not UI pixels, but it trains wrong expectations. Fix if touching product scope.

19. **Icon-only external open / GitHub on cards** — R-04 (soft), human skill
    Open site is the hub’s main job but is a 16px icon. Tap target and discoverability are weak vs the full-width Analytics button (layoutmobile / human).

20. **Login is a generic centered card** — R-20, R-05
    Functional and fine for ENERGY 1, but brand is logo + name only; no identity motif beyond that. Low priority if hub grid carries identity.

**No.** Sharif Lab only has the first-party `track.js` → `POST /api/ingest/events` pipeline. There is no built-in Plausible, GA, Vercel Analytics bridge, or server-side crawl of your other hosts.

| Add a third-party embed later | No | New work; more surface area |
| **Drop analytics; keep hub** | Aligns with DESIGN.md | Less product, honest product |
